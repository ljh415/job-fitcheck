# MCP 계획 배경 — 논의 요약 (구체화 전)

> **작성**: 2026-07-27, Codex 논의 요약(RAG 서브프로젝트 대화 중 MCP 파트만 발췌)
> **상태**: 결정 배경만 정리됨. 세부 도구 목록·전송 방식·인증·쓰기 승인 정책은 아직 미확정.

## 논의 배경

처음에는 현재 RAG Core 위에 얇은 MCP 어댑터를 붙이는 방안을 논의했다. 이후 MCP는 RAG 전용 인터페이스보다 `Job FitCheck` 전체 기능을 Claude·Codex 같은 외부 AI가 사용할 수 있게 하는 공통 인터페이스로 구성하는 편이 적절하다고 판단했다.

## 향후 MCP 제공 기능 예시

- 등록 공고 조회·필터링
- 지원할 만한 공고 우선순위 분석
- 특정 공고의 적합도·부족 역량 분석
- 프로필과 시장 요구사항 비교
- RAG 기반 공고 시장 분석
- 필요하면 웹 검색 기반 최신 정보 조사

## MCP를 RAG 이후로 미룬 이유

1. 현재 RAG에는 자연어 질문 라우팅, 멀티턴 대화, 하이브리드 검색 선택, 근거 표시가 아직 남아 있다.
2. 미완성 RAG API를 먼저 MCP 도구로 노출하면 RAG 변경 때마다 MCP 인터페이스도 함께 변경될 수 있다.
3. MCP 내부에 검색·분석 로직을 다시 만들지 않고, 안정화된 RAG Core와 메인 프로젝트 기능을 그대로 호출해야 중복 구현을 피할 수 있다.
4. MCP는 RAG뿐 아니라 Job FitCheck의 기존 적합도·공고 상태·프로필·비교 기능까지 함께 검토해야 하므로 메인 프로젝트 기능 경계 확인도 필요하다.
5. 현재 목표는 MCP 경험보다 대화형 근거 기반 RAG를 먼저 완성하는 것이다.

## 진행 순서

```
대화형 근거 기반 RAG
  → RAG 모듈 안정화
  → Job FitCheck 전체 MCP 설계·구현
  → 필요하면 웹 검색 기능도 별도 도구로 포함
```

## 웹 검색 관련 방향

웹 검색은 기존 로컬 RAG Core에 섞지 않는다. 구현한다면 MCP 구성 시점에 별도 기능으로 검토하고, 로컬 corpus 근거와 웹 검색 근거를 구분해서 반환한다. Claude/Codex가 이미 제공하는 웹 검색을 재사용할 수 있다면 Job FitCheck에 별도 웹 검색 기능을 만들지 않는 선택지도 남겨둔다.

## 아직 미확정

MCP의 세부 도구 목록, 전송 방식, 인증, 쓰기 기능 승인 정책은 아직 확정하지 않았다. RAG 안정화 이후 메인 프로젝트 코드의 재사용 가능 경계를 확인하면서 별도 계획과 Todo로 구체화할 예정이다.
